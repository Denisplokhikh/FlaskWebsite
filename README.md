Практическая работа №1

1. Предметная область проекта
В качестве предметной области выбран веб-сайт блог-платформы.
Проект представляет собой онлайн-платформу, где пользователи могут:
•	регистрироваться и авторизоваться;
•	создавать и публиковать статьи;
•	просматривать публикации других пользователей;
•	оставлять комментарии;
•	ставить лайки.
Основная цель проекта - обеспечить удобный и масштабируемый сервис для публикации и чтения статей.

2. Выбранная архитектура
Для реализации проекта используется микросервисная архитектура.
Это означает, что система будет разделена на независимые сервисы, каждый из которых отвечает за свою часть функциональности.
Преимущества выбранной архитектуры:
•	масштабируемость отдельных компонентов;
•	независимое развертывание сервисов;
•	упрощение поддержки и развития проекта;
•	возможность использовать разные технологии для разных сервисов.
3. Основные части проекта
Проект состоит из следующих микросервисов:
3.1. Сервис пользователей (User Service)
•	регистрация пользователей;
•	авторизация и аутентификация;
•	управление профилем пользователя.
3.2. Сервис публикаций (Post Service)
•	создание и редактирование постов;
•	удаление публикаций;
•	получение списка статей;
•	хранение контента постов.
3.3. Сервис комментариев (Comment Service)
•	добавление комментариев;
•	удаление комментариев;
•	привязка комментариев к постам.
3.4. Сервис взаимодействий (Like Service)
•	обработка лайков и дизлайков;
•	подсчет реакций на посты.
3.5. Frontend (клиентская часть)
•	интерфейс пользователя;
•	отображение постов и комментариев;
•	взаимодействие с API микросервисов.
3.6. API Gateway (опционально)
•	единая точка входа в систему;
•	маршрутизация запросов к микросервисам.

4. Pipeline проекта
Процесс разработки и доставки проекта включает следующие этапы:
1.	Изменения фиксируются через commit в Git.
2.	Создается Pull Request в dev-ветку.
3.	После успешной проверки изменения попадают в dev-ветку.
4.	После стабилизации версия переносится в main (production).
5.	Сборка и деплой проекта выполняется через Docker.

5. Используемые технологии
В проекте планируется использовать следующие технологии:
Backend:
•	Python
•	Flask (для создания REST API микросервисов)
Инфраструктура:
•	Docker (контейнеризация микросервисов)
•	Docker Compose (оркестрация контейнеров)
•	Git (контроль версий)
•	GitHub (хостинг репозитория)

Заключение
Данный проект представляет собой микросервисную блог-платформу, разработанную с использованием Flask и контейнеризации Docker. Архитектура позволяет легко масштабировать систему и независимо развивать отдельные компоненты.
